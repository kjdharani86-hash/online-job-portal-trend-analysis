Black-Box Testing (Functional)
  • Equivalence Partitioning (EP):
    • CGPA valid partition: [0.00, 10.00]. Invalid partitions: < 0.00, > 10.00.
    • Phone number partition: 10 numeric digits. Invalid: alphabetic or length ≠ 10.
  • Boundary Value Analysis (BVA):
    • CGPA tested at boundaries: -0.01 (Reject), 0.00 (Accept), 6.00 (Cutoff boundary), 10.00 (Accept), 10.01 (Reject).
White-Box Testing (Structural)

Basis Path Testing & Cyclomatic Complexity for isEligible():

Formula: V(G) = P + 1 (where P = number of predicate decisions)
Predicates: (1) CGPA ≥ Cutoff, (2) Dept == 'ALL', (3) Dept in AllowedList
V(G) = 3 + 1 = 4 Independent Execution Paths
  1. Path 1: CGPA < Cutoff → Throws IneligibleCandidateException.
  2. Path 2: CGPA ≥ Cutoff & Dept == 'ALL' → Returns true.
  3. Path 3: CGPA ≥ Cutoff & Dept ∈ List → Returns true.
  4. Path 4: CGPA ≥ Cutoff & Dept ∉ List → Throws IneligibleCandidateException.

5.2 Software Cost & Effort Estimation (Basic COCOMO Model)

The Constructive Cost Model (COCOMO) by Barry Boehm was applied to estimate software development effort, schedule duration, and recommended staffing. The project falls under the Organic Mode (small team, well-understood academic domain, and familiar execution environment).

COCOMO Mathematical Equations (Organic Mode)
Effort: E = ab × (KLOC)bb [person-months]
Development Time: D = cb × (E)db [months]
Staff Size: SS = E / D [persons]
Constants for Organic Mode:
ab = 2.4, bb = 1.05, cb = 2.5, db = 0.38
Delivered Source Code Size (KLOC)
  • Java Backend (Model, DAO, Service, Main, Util): 1,120 LOC
  • Python Analytics & Web Dashboard (Flask, Preprocessing, Plots): 510 LOC
  • SQL Schema, Seed Data & Analytical Queries: 190 LOC
  • Total Delivered Source Code (KLOC): 1.82 KLOC
Step-by-Step Project Management Calculations
1. Estimated Effort (E): 2.4 × (1.82)1.05 = 4.50 Person-Months
2. Development Duration (D): 2.5 × (4.50)0.38 = 4.43 Months (≈ 16 Weeks)
3. Recommended Staff Size (SS): 4.50 / 4.43 = 1.02 ≈ 1 Developer
4. Development Productivity: 1,820 LOC / 4.50 PM = 404 LOC / Person-Month
Validation: The calculated timeline (4.43 months) corresponds directly to an academic semester (August to November), confirming optimal resource utilization.

5.4 Risk Management (RMMM Plan)

The Risk Mitigation, Monitoring, and Management (RMMM) plan establishes formal procedures to eliminate or mitigate project risks before they compromise system integrity.

Risk Category Identified Risk Description Prob (P) Impact (I) Mitigation Strategy Management & Monitoring
Data Integrity Duplicate applications submitted for same vacancy. High (0.8) High Dual-layer protection: DB compound UNIQUE constraint + Service layer pre-check. Caught via DuplicateApplicationException; flash alert shown to user.
